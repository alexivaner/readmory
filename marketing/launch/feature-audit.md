## Routes and architecture

The workspace is the root App Router page with hash navigation: dashboard, library, knowledge, notes, rhythm, statistics, import and settings. Book details are local component state. `/welcome/` is the introduction route. There are no server API routes for the library. React calls a SQLite worker for import/storage; statistics run on normalized reading records. Books, annotations, sessions, attempts, snapshots, knowledge, topics and reflections preserve source provenance.

Reviewed README, PRIVACY, BRANDING, ARCHITECTURE, IMPLEMENTATION, READING_HISTORY, app routes/components, core/import/storage/knowledge/analytics/export/enrichment packages, test fixtures and E2E suite. Earlier paragraphs of IMPLEMENTATION/ARCHITECTURE describe outdated release scope (including grouping, deployment and social cards). Later implementation sections, current code and current tests take precedence. The implemented statistics PNG card is narrower than a general social-card renderer.

## Claims deliberately excluded

No AI assistant, semantic search, automatic cloud sync, scheduled spaced repetition, native desktop USB discovery, reading goals/streak awards, social network, complete historical reread counts, universal reader firmware support or automatic extraction of arbitrary private documents. No comparison chart between books beyond the actual rankings. Connections are shared-topic lists, not a graph or AI discovery.

## Chosen story

Remember the books → see the reading → revisit the ideas → keep a portable local copy. Lead with real covers and the calendar; make source-aware statistics and the share card the distinctive discoveries. Keep technical caveats in plain language: imported history can be incomplete, estimates stay labeled, and backups matter.
